# 14 — Packaging, One-Command Setup and GitHub Release

Owner: build agent (wave 7, after sheet 04 is built and verified against a real MW2 install)
Status: implementation-ready
Depends on: 00 (§2 D2, D3, D5, D20, D21; §4), 01, 02 (Taskfile, scripts, `.gitignore`), 04 (exporter), 13 (tests used by CI)

The end-user story: clone the repository from GitHub, put **your own** game files into one folder, run one script, play. The script checks the machine, builds the exporter, turns the user's MW2 install into a pack, builds the game, and writes a launcher. Nothing copyrighted is ever in the repository or produced by anyone but the user, on the user's machine.

---

## 1. Purpose

- A newcomer with a fresh Linux machine, a Doom IWAD and an MW2 multiplayer install gets a playable game by following the README and running `./setup.sh`.
- The repository builds from a clean GitHub clone, without sibling checkouts (`../room`, `../iw4L`) and without Git LFS.
- CI on GitHub proves the code builds and tests pass without any game data.

## 2. Scope / Out of scope

In scope: the `games/` folder convention; `setup.sh`; `play.sh` generation; switching iw4L from path to pinned git dependencies (with a local-override escape hatch for development); removing LFS pointer files; locating IWAD and soundfont from `games/`; end-user README; GitHub Actions CI; release checklist; the publish step itself (after the user confirms).

Out of scope: Windows/macOS setup scripts (Windows `setup.ps1` is the next sheet; D21), prebuilt binary releases (possible later — the game binary contains no game data), an installer GUI, auto-updating.

## 5. Detailed design

### 5.1 The `games/` folder (the only thing the user provides)

```text
games/
  iw4/            Modern Warfare 2 (2009) multiplayer install — a copy or a symlink.
                  Must contain zone/ and main/ as installed by Steam (iw4mp.exe folder).
  doom/           One or more Doom IWADs (the user's own): doom2.wad, doom.wad, plutonia.wad,
                  tnt.wad, doom1.wad (shareware), freedoom2.wad, freedoom1.wad.
  soundfont.sf2   Optional: a General MIDI soundfont for music.
```

`games/` is gitignored except `games/README.md`. The exporter sets `IW4L_GAMES=<repo>/games` (iw4L convention: games root containing `iw4`). Symlinks are allowed everywhere (no copying a 10+ GB install).

IWAD choice when several are present: the first found in the order `doom2.wad, doom.wad, plutonia.wad, tnt.wad, freedoom2.wad, freedoom1.wad, doom1.wad`; `play.sh --iwad <name>` overrides; `play.sh --list` prints what was found.

### 5.2 `setup.sh`

Bash, `set -euo pipefail`, Linux only (prints a clear message and exits on other systems). Every step prints one line `[n/8] …` and appends details to `setup.log`. Re-running is safe and fast (each step skips work that is already done unless `--clean` / `--reexport`).

1. **Inputs.** Check `games/iw4` exists and looks like MW2 MP (`zone/` contains `common_mp.ff` somewhere below it, and the default export zone `mp_rust.ff`); check `games/doom/` has at least one file whose first 4 bytes are `IWAD`. On failure print exactly what is missing and where, pointing to `games/README.md`, exit 1.
2. **Rust.** If `cargo`/`rustup` are missing, print the official rustup install command and exit 1 (the script never pipes a remote installer into a shell by itself). If present, `rustup toolchain install` the version from `rust-toolchain.toml` (no-op when installed) and verify `rustc --version` ≥ 1.97.1.
3. **System libraries.** Check `cc`, `pkg-config`, and `pkg-config --exists alsa wayland-client xkbcommon libudev`. If anything is missing, detect the package manager and print the one install line (apt: `sudo apt install build-essential pkg-config libasound2-dev libwayland-dev libxkbcommon-dev libudev-dev`; dnf and pacman equivalents), then exit 1. The script never runs `sudo` itself.
4. **Build the exporter.** `cargo build --release` in `tools/dmw_export` (first build ≈ 10–15 min; say so before starting).
5. **Export.** If `packs/mw2/manifest.json` is missing, or `--reexport`, or its `iw4l_rev`/generator differ from the current build: run `dmw_export --out packs/mw2` with `IW4L_GAMES=$PWD/games`. Map exit codes to plain-English messages (2: MW2 not found at games/iw4; 3: load refused — iw4L log path; 4: a weapon failed — list from `report.json`; 5: disk). Print the one-line-per-weapon summary.
6. **Build the game.** `cargo build --release --bin doommw2`.
7. **Smoke test.** Run the game headless for 70 tics on the chosen IWAD with the real pack (`room` test harness binary or a `--smoke` flag added to the game: init, load E1M1/MAP01, run tics, exit 0). Fail the setup if MW2 mode did not turn on, naming the reason from the log.
8. **Launcher.** Write `play.sh` (executable): `exec target/release/doommw2 -iwad "games/doom/<chosen>" -mw2pack packs/mw2 -mb 128 ${SF2:+-sf2 games/soundfont.sf2} "$@"`, plus `--iwad`/`--list` handling. Print "Done. Run ./play.sh".

`-mb 128` works around room's `Z_FreeTags` 2000-block limit (sheet 13 §11); remove it when that engine bug is fixed (separate task).

### 5.3 iw4L as a pinned git dependency

Root `Cargo.toml` `[workspace.dependencies]` and `tools/dmw_export/Cargo.toml`:

```toml
weapon_iw4 = { git = "https://github.com/vladtrc/iw4L", rev = "fc3d8eaf6045cb131eb74cd41954f0c4922b9913" }
# … same rev for every iw4L crate
```

Cargo resolves crates inside the git repository by name, so one URL + rev serves all of them; workspace inheritance inside iw4L keeps working as it did for path dependencies (verify with `cargo tree` from a fresh clone in a temp directory, no `../iw4L` present).

Local development against a checkout: `.cargo/config.toml.example` documents

```toml
[patch."https://github.com/vladtrc/iw4L"]
weapon_iw4 = { path = "../iw4L/crates/weapon_iw4" }
# …
```

copied to `.cargo/config.toml` (gitignored) by developers who want it.

`tools/check-iw4l-rev.sh`: compare `IW4L_REV` against the `rev` in both manifests and the `source` lines in both `Cargo.lock` files; when `../iw4L` exists, also keep the old check.

### 5.4 No Git LFS

- Delete `doom1.wad` and `soundfonts/SC55Soundfont-1.2b/*.sf2` pointer files and the LFS lines in `.gitattributes`.
- `demo_playthrough` looks for `games/doom/doom1.wad`, then `DMW_DOOM1_WAD`; the existing "real IWAD or skip with notice" rule (02 §5.4) stays.
- Music: room's audio init uses `-sf2 <path>` if given, else `games/soundfont.sf2` if present, else no music with one `info!` line (today it warns about the pointer file).

### 5.5 README

Top of the file, for players:

1. What it is (one paragraph, one screenshot rendered with the **fixture** pack — never MW2 assets).
2. Requirements: Linux, ~4 GB free disk for the build, your own MW2 (2009) multiplayer install and your own Doom IWAD.
3. Steps: `git clone …`, put files in `games/` (copy of §5.1), `./setup.sh`, `./play.sh`.
4. Controls (00 §8.3 defaults; `doommw2.toml` to rebind).
5. Troubleshooting: the setup exit messages, `setup.log`, where iw4L logs go.
6. Legal: you must own the games; no game data is included or downloaded; the pack stays on your machine; not affiliated with or endorsed by Activision, Infinity Ward, id Software, Bethesda or ZeniMax; trademarks belong to their owners; GPL-3.0-or-later with Apache-2.0 portions (NOTICE).

Then a developer section: specs, Taskfile, fixture pack (`-fixturepack`), tests, contribution rules (AGENTS.md).

### 5.6 CI (`.github/workflows/ci.yml`)

On push/PR to `main`: Ubuntu latest; install the §5.2 step 3 packages; toolchain from `rust-toolchain.toml`; cache `~/.cargo` and `target`; `tools/fetch-freedoom.sh`; `cargo check`, the three-step lint, `cargo test --workspace --exclude c2rust-intermediate -- --skip demo_playthrough` with `DMW_IWAD=wads/freedoom1.wad`. A second, manually triggered job builds `tools/dmw_export` (slow). CI never needs game data or secrets.

### 5.7 Release checklist (`docs/RELEASE.md`) and publishing

Before the first public push:

- [ ] `git grep` and a history scan confirm no game data, no packs, no `.env`, no screenshots with MW2 assets, no large binaries (`git rev-list --objects --all` size check).
- [ ] Fresh clone in a temp dir builds and tests with no `../room`, no `../iw4L`, no LFS.
- [ ] `./setup.sh` run end to end on the maintainer's machine with real files; the smoke test passes; `./play.sh` plays.
- [ ] README legal section present; NOTICE complete.
- [ ] Repository name and description chosen by the owner (see §6, trademark note).

Publishing (`gh repo create`, first push, tag `v0.1.0`) is an outward-facing action: the lead performs it only after the owner explicitly confirms the repository name, visibility (public/private) and that the checklist is complete.

## 6. Error handling and edge cases

| Case | Behaviour |
|---|---|
| `games/iw4` is the single-player install | step 1 fails: no `common_mp.ff`; message says "multiplayer install needed" |
| MW2 install from a non-Steam source | accepted if the zone files are present (iw4L reads the files, not Steam) |
| Pack already exported by an older build | step 5 re-exports automatically (generator/rev mismatch) |
| Disk full during export | exporter exit 5; previous pack kept (04 §5.9) |
| Trademarks | "MW2" and "DOOM" are trademarks; a repository named after both invites takedown risk. The owner decides the name; the README never uses logos or official art |
