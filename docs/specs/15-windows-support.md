# 15 — Windows Support

Owner: build agent (wave 8)
Status: implementation-ready
Depends on: 00 (D21 superseded here), 01, 02, 04, 13, 14 (setup.sh, play.sh, CI, `games/` convention)

IW4DOOM must build, test and play on Windows 10/11 (x86-64, MSVC toolchain) with the same end-user story as Linux: clone, put your own game files in `games\`, run one script, play.

---

## 1. Purpose

- Windows players get `setup.ps1` + `play.bat` equivalent to `setup.sh` + `play.sh`.
- The code base compiles for `x86_64-pc-windows-msvc` with no Linux-only assumptions (paths, libc calls, symlinks, audio, window/cursor handling).
- GitHub Actions proves it on a real Windows runner on every push: build + the full test suite on Freedoom (no game data in CI).

## 2. Scope / Out of scope

In scope: making `room`, `crates/*` and `tools/dmw_export` compile and run on Windows MSVC; `setup.ps1`; `play.bat` (generated); Windows paths for `games\`, config (`%APPDATA%\iw4doom\iw4doom.toml` fallback), saves, logs; a `windows-latest` CI job; README Windows sections (requirements, Steam paths, symlink vs junction vs copy, troubleshooting); `docs/RELEASE.md` Windows checks.

Out of scope: macOS; prebuilt Windows binaries/installer (possible later; the binary contains no game data); 32-bit Windows; ARM64.

## 3. Facts to start from

| Fact | Source |
|---|---|
| winit, wgpu, rodio/cpal, rustysynth are cross-platform | upstream crates |
| iw4L ships Windows builds (`docs/WINDOWS.md`, `make build-windows`), so the exporter's Bevy/asset stack builds on Windows | iw4L README at fc3d8ea |
| `room` uses the `libc` crate for C-shaped file I/O (`FILE`, `fopen`, `fseek`, `printf`, …) and was developed on Linux; Windows has never been tried | room sources |
| `doomgeneric-sys` (C, `cc`) is a **dev-dependency** used by layout/regression tests only | 02 |
| Symlinks need admin or Developer Mode on Windows; directory junctions (`mklink /J`) do not | Windows |
| Steam default library: `C:\Program Files (x86)\Steam\steamapps\common\` (MW2: `Call of Duty Modern Warfare 2`; DOOM + DOOM II: `Ultimate Doom`) | Steam |

## 5. Detailed design

### 5.1 Make it compile and behave

1. Locally: `rustup target add x86_64-pc-windows-gnu` and `cargo check --workspace --exclude c2rust-intermediate --target x86_64-pc-windows-gnu --all-targets` (and the same for `tools/dmw_export`) to find compile errors without a Windows machine. `check` does not link; if a build script needs a C cross compiler, install-free workarounds first, otherwise report it. The authoritative check is the MSVC CI job (§5.4).
2. Fix every Linux-only assumption found, e.g.: `libc` functions or constants missing on Windows (replace with `std` where the C semantics allow, or cfg-gate), `/` path joins written as strings, `HOME`/`XDG_*` lookups (add `%APPDATA%`/`%LOCALAPPDATA%`), file modes, `.savegame/` and config directories, line endings in text files the engine parses, case-sensitive WAD lookups (Windows is case-insensitive; keep behaviour identical on Linux).
3. Vanilla parity must hold on Linux (`demo_playthrough`) after every change.

### 5.2 Runtime behaviour on Windows

- Window/cursor: winit `CursorGrabMode::Confined` is supported on Windows (`Locked` is not; the existing fallback order handles it — verify the log line).
- Audio: rodio default output (WASAPI).
- Config: `.\iw4doom.toml`, then `%APPDATA%\iw4doom\iw4doom.toml` (and `doommw2.toml` fallbacks as on Linux).
- Paths printed in logs use the native separator.

### 5.3 `setup.ps1`

PowerShell 5.1+ (ships with Windows 10/11), `Set-StrictMode -Version Latest`, `$ErrorActionPreference = 'Stop'`. Same eight steps and messages as `setup.sh` (§5.2 of sheet 14), with Windows specifics:

1. Inputs: `games\iw4` (folder, junction or symlink) contains `zone\**\common_mp.ff` and `mp_rust.ff`; `games\doom\` has an IWAD (first 4 bytes `IWAD`). On failure print exact instructions, including how to make a junction: `cmd /c mklink /J games\iw4 "C:\Program Files (x86)\Steam\steamapps\common\Call of Duty Modern Warfare 2"` (no admin needed), and offer the detected Steam path when it exists (read `libraryfolders.vdf` under the Steam install found via the registry `HKCU:\Software\Valve\Steam\SteamPath`).
2. Rust: if `cargo` is missing, print the rustup-init.exe download URL (https://rustup.rs) and exit 1 — never download or run installers itself. Require rustc ≥ 1.97.1; `rustup toolchain install` the pinned toolchain.
3. Build tools: MSVC linker present (`link.exe` via `vswhere`, or rustup's own check). If missing, print the "Visual Studio Build Tools, Desktop development with C++" instruction and exit 1.
4–6. Build exporter, export (`IW4L_GAMES`/`DMW_MW2_GAMES` = `$PWD\games`), build game — identical logic and exit-code messages to `setup.sh`.
7. Smoke test (`cargo test --release -p room --test setup_smoke`).
8. Write `play.bat` (`@echo off` + `target\release\iw4doom.exe -iwad "games\doom\<chosen>" -mw2pack packs\mw2 -mb 128 [-sf2 games\soundfont.sf2] %*`, with `--list`/`--iwad` handled by a small PowerShell helper or batch logic).

Also support `-Games <dir>`, `-Reexport`, `-Clean`; log to `setup.log`. If execution policy blocks scripts, the README tells users to run `powershell -ExecutionPolicy Bypass -File setup.ps1`.

### 5.4 CI

Add a `windows` job to `.github/workflows/ci.yml`: `runs-on: windows-latest`; toolchain from `rust-toolchain.toml`; cache cargo; fetch Freedoom (PowerShell equivalent of `tools/fetch-freedoom.sh`, same pinned tag and hashes — add `tools/fetch-freedoom.ps1`); `cargo check --workspace --exclude c2rust-intermediate --all-targets`; `cargo test --workspace --exclude c2rust-intermediate -- --skip demo_playthrough` with `DMW_IWAD` set. The exporter Windows build is part of the existing manual exporter job (add a Windows matrix entry). No game data, no secrets.

### 5.5 README

Add Windows to badges and Quick start (PowerShell commands), Windows requirements (Rust via rustup-init.exe, Visual Studio Build Tools C++ workload), where Steam puts MW2 and DOOM on Windows, the junction command, execution-policy note, Windows troubleshooting. Linux instructions stay as they are.

## 6. Error handling and edge cases

| Case | Behaviour |
|---|---|
| Steam library on another drive | setup reads `libraryfolders.vdf`; otherwise the user makes the junction to wherever it is |
| Path with spaces | all paths quoted in scripts and `play.bat` |
| Antivirus quarantining a freshly built exe | README troubleshooting note |
| `games\iw4` symlink created without Developer Mode | fails; message recommends a junction |

## 11. Contract changes requested

1. 00 D21: Windows (x86-64, MSVC) is a supported platform alongside Linux.
2. One command on both systems (user request via the lead, 2026-10-16; supersedes §5.3's `setup.ps1` + generated `play.bat` and sheet 14's `setup.sh` + generated `play.sh`):
   - Linux: tracked `iw4doom.sh`; Windows: tracked `iw4doom.bat` (double-clickable) running `powershell -NoProfile -ExecutionPolicy Bypass -File iw4doom.ps1 %*`. Same eight steps as sheet 14 §5.2, step 8 starts the game with any extra arguments passed through. Flags: `--list`, `--iwad NAME`, `--games DIR`, `--reexport`, `--clean`, `--setup-only` (PowerShell spellings `-List` etc. accepted). `setup.sh` remains as a shim for `iw4doom.sh --setup-only`.
   - Later runs: cargo's freshness check plus the pack manifest decide; the smoke test runs only when the game binary or the pack changed since the last pass (stamp `target/release/.iw4doom-smoke-ok`).
   - Missing prerequisites: when stdin is a terminal and `CI`/`IW4DOOM_NONINTERACTIVE` are unset, the script shows the exact install command and asks `[Y/n]`; on yes it runs it (Linux: the distribution's package install with `sudo`, the official rustup installer with `-y`; Windows: `winget install Rustlang.Rustup` / `Microsoft.VisualStudio.2022.BuildTools` with the VC tools workload). On no, or without a terminal, it prints the instructions and exits 1 (the old behaviour). This replaces "never runs sudo / never downloads or runs installers".
   - Log: `iw4doom.log` (was `setup.log`). Tests: `tools/test-iw4doom-launcher.sh` / `.ps1` (T14.2-T14.4, T15.3) in CI.
   - 00 §4.1 file list: `iw4doom.sh`, `iw4doom.bat`, `iw4doom.ps1`, `tools/fetch-freedoom.ps1`, `tools/test-iw4doom-launcher.{sh,ps1}`, `.gitattributes` (LF checkouts; CRLF for `.bat`) replace `play.sh`/`setup.log`.
3. Config lookup on Windows: `%APPDATA%` stands in for `XDG_CONFIG_HOME` when that is unset (`%APPDATA%\iw4doom\iw4doom.toml`, then the `doommw2` fallback), as §5.2 says.
